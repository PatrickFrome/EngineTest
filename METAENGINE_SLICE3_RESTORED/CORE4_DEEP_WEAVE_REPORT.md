# Core-4 Deep Weave — Engines 1–4

## Engine 1 — Destruktion COMPLETE 0.13
Role in 1.3: **destructive/interrogative destabilizer**.

It receives hybrid agenda, disagreements and peer returns, then generates frame-atom probes, residual questions and second-order destruction. Its purpose is to prevent the shared mesh from treating its current units of analysis as natural or final.

## Engine 2 — Destruktion integrated 0.10
Role in 1.3: **operator ecology / reversible mutation**.

It asks whether the current analytical operator is itself the problem, generates reversible operator candidates, preserves retirement conditions and in round 2 can localize operator selection instead of globalizing one ontology across the source.

## Engine 3 — Destruktion UNIFIED 0.15
Role in 1.3: **semantic-boundary and lineage differential**.

It prevents the shared semantic bus from erasing distinctions while normalizing outputs. It explicitly searches for canonicalization residue and makes incompatibility between vocabularies an analyzable object rather than a formatting problem.

## Engine 4 — Destruktion portable 0.16
Role in 1.3: **scope / parse / counterfactual gate**.

It tests attribution, polarity, modality and parse conditions; it may abstain when cues are insufficient. In round 2 it attacks peer readings by changing the structural cue that licensed them.

## Recursive braid

Round 1 is intentionally divergent. Round 2 exposes each engine to the other three returns:

`E1 destruction → E2 operator mutation → E3 semantic differential → E4 scope/counterfactual → return to E1/E2/E3/E4 → ORIGINAL_SOURCE`

The actual runtime executes all four in parallel per round; the arrow above describes conceptual dependency, not serial scheduling.

## Provenance firewall

The re-entry dossier contains two explicitly separated classes:

- `ORIGINAL_SOURCE` — primary source material;
- hybrid agenda / disagreements / peer returns — derived context.

Outputs produced from the latter are downgraded to `SECOND_ORDER_GENERATIVE_UNTIL_REGROUNDED_ON_ORIGINAL_SOURCE`.

## Current limit

Native intake of all four engines is executed in both rounds, but the differentiated Core-4 transforms are currently implemented as meta-level architecture projections. The next native-deepening stage should compile those probes into each lineage's own advanced manifests/subcommands (interrogative/frame-atom induction, operator mutation/ecology, shared-boundary differential, parse/counterfactual programs) and compare native-vs-projected returns.
