## Что НЕ сработало / требует улучшения

### Проблема 1: Симулированные измерения качества

Baseline и with_mechanism quality смоделированы (random). Не реальные запуски оркестратора.

**Решение:** Запустить реальные эксперименты по переносу — применить механизм к целевому движку через адаптер, измерить реальное качество.

### Проблема 2: Нет AssimilationGate интеграции

A1→A2 требует AssimilationGate receipt (конституционный guard). Текущий тестер останавливается на A1.

**Решение:** Интегрировать AssimilationGate из metaengine/assimilation.py. Gate требует:
- Исходный механизм A1
- Эксперимент по переносу (перекрестный мир)
- Внешнюю верификацию

### Проблема 3: Нет анализа переносимости по конкретным движкам

Какие движки получают больше всего пользы от механизмов engine_16? Нативные (01-04) или эталонные (05-15)?

**Решение:** Добавить анализ переносимости по движкам в summary.

### Проблема 4: Все механизмы из engine_16

Все 12 механизмов из engine_16 (LLM). Нет разнообразия источников.

**Решение:** Извлечь механизмы из других движков (через dialectical_graph nodes, не только LLM response).

## Лучшее решение для следующего шага

**Phase 46: Тестирование точности саммаризатора** — расширяет RLAIF для проверки соответствия саммари LLM фактическим рассуждениям. Неточное саммари → более низкая награда.

**Почему Phase 46 следующий:**
1. Фаза 44 извлекла следы рассуждений (фактическое рассуждение)
2. Фаза 45 протестировала перенос между движками
3. Фаза 46 проверяет, соответствует ли саммари LLM фактическому рассуждению
4. В PDF Panfilov (Рис 8) показано, что саммаризаторы бывают неточными
5. Это напрямую связано с конституционным требованием PRESERVE_ABSTENTION

**Параллельно:** улучшить кросс-модельный перенос (Phase 45.1 refinement):
- Реальные эксперименты по переносу (не симуляция)
- Интеграция AssimilationGate (A1→A2)
- Анализ переносимости по движкам
- Разнообразные источники механизмов
