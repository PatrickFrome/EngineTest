## Executive assessment

The strongest new idea is not another operator but a second **interrogative family**. Previous source mutation could add or alter operators while leaving the kind of question largely inside a relation-genesis vocabulary. The regression package demonstrates a stronger transition:

`source pressure → interrogative-family birth → local cross-family ecology → boundary/residual preservation → downstream polyphonic abstention`

The first new family is `PROCESSUAL_HERMENEUTIC_PROFILE`. It asks temporal, enactment, practice/material, absence/trace and address/response questions independently of `RELATION_GENESIS_PROFILE`.

This matters because epistemic nonlinearity now occurs at three different levels:

1. **operator novelty** — open-set 0.10 can say that no known operator is sufficient;
2. **interrogative-family novelty** — Studio 0.7 can say that a passage may require a different kind of question;
3. **localization loss** — the preserved 0.9 audit can say that globally composing local winners would falsify provenance.

These layers are deliberately not collapsed into one universal meta-operator.

## Strong solutions integrated

### 1. Independent interrogative-family routing

Implemented as a Studio experimental extension in `studio/independent-family/`.

The processual family recognizes source-local pressure across eight signal families:

- `TEMPORALITY`;
- `EXPECTATION`;
- `ENACTMENT_PRACTICE`;
- `REPETITION_RHYTHM`;
- `MATERIAL_MEDIATION`;
- `ABSENCE_WITHDRAWAL`;
- `TRACE_DISCLOSURE`;
- `ADDRESS_RESPONSE`.

Initial local profiles:

- `TEMPORAL_ENACTMENT`;
- `PRACTICE_MEDIATION`;
- `ABSENCE_DISCLOSURE`;
- `RESPONSIVE_ENACTMENT`.

Relation and processual profiles can co-occur as `MULTI_FAMILY_LOCAL_PROFILE` without being fused into a global ontology.

### 2. Unicode lexical-boundary repair

The supplied regression report exposed a real false positive: cue `call` activated inside `locally`. Studio 0.7 reconstructs signal matching with Unicode letter/number lexical boundaries and locks this into a regression test.

This is methodologically important because it prevents an apparent gain in hermeneutic sensitivity from being caused by substring noise.

### 3. Source-birth gate

A family candidate is not admitted merely because the detector lists it. The ecology runner verifies that the origin refinery contains the required local profile and that the origin living trace contains the corresponding source-forced method mutation.

The supplied controlled regression confirms four source-born candidates before they enter local competition.

This remains an **internal mechanics gate**, not semantic validation.

### 4. Cross-family local composition

The six-window benchmark is reproduced from code:

| Window | Integrated result |
|---|---|
| W1 Temporal enactment | `SELECT_LOCAL_WINNER → TEMPORAL_ENACTMENT_SOURCE_BORN` |
| W2 Practice/material mediation | `SELECT_LOCAL_WINNER → PRACTICE_MEDIATION_SOURCE_BORN` |
| W3 Absence/trace | `SELECT_LOCAL_WINNER → ABSENCE_DISCLOSURE_SOURCE_BORN` |
| W4 Relation control | `SELECT_LOCAL_WINNER → GEVIERT_CO_CONSTITUTIVE_GATHERING` |
| W5 Cross-family composition | `LOCAL_COMPOSITION → GEVIERT... + TEMPORAL...` |
| W6 Descriptive negative control | `ABSTAIN_UNRESOLVED` |

The synthesis remains `PRESERVE_POLYPHONIC_LOCALITY`.

W5 is the important structural step: the system composes two independently born interrogative families locally without claiming that they form one global ontology.

### 5. Downstream provenance preservation

Implemented in `ecology-downstream.mjs`.

It translates micro-local ecology into explicit living/expert artifacts:

- `LOCAL_INQUIRY`;
- `SOURCE_BORN_OPERATOR`;
- `LOCAL_RESIDUAL`;
- `HERMENEUTIC_BOUNDARY`.

Local expert outcomes remain routing-level only:

- `QUALIFIED_LOCAL_ROUTING`;
- `QUALIFIED_LOCAL_COMPOSITION`;
- `RIVALS_UNRESOLVED`;
- `INSUFFICIENT_LOCAL_ROUTING`.

The controlled benchmark preserves five boundaries and one residual, then returns:

`POLYPHONIC_GLOBAL_ABSTENTION`

with:

`thesis_allowed=false`

This prevents the downstream living/expert layer from undoing the nonlinearity produced upstream by manufacturing one corpus-level thesis.

### 6. Non-promoting family probe

New command:

```bash
node studio/studio.mjs family:probe <source.docx> --out <dir> [--language <tag>]
```

The probe can detect processual-family pressure, but its output is explicitly:

`EXPERIMENTAL_PROBE_NOT_SOURCE_BIRTH`

with:

- `source_birth_confirmed=false`;
- `promotion_forbidden=true`.

It therefore generates a research hypothesis rather than silently creating a new canonical family.

## Three ecology layers retained separately

### A. Open-set ecology — current frozen 0.10 baseline

Question:

> Is the necessary operator absent from the known registry?

It handles `UNKNOWN_OPERATOR_FAMILY`, `ADD_OPERATOR`, known/open-set rivalry and local abstention.

### B. Independent-family ecology — Studio 0.7

Question:

> Does this passage require a qualitatively different kind of interrogative operation?

It handles relation-genesis versus processual-hermeneutic families and local cross-family composition.

### C. Localization-loss audit — preserved 0.9 compatibility layer

Question:

> What would become falsely warranted if every local operator were globalized?

It retains the stronger negative-control decision:

`REJECT_GLOBAL_COLLAPSE_PRESERVE_WINDOW_PROVENANCE`

These are complementary rather than successive replacements.

## What was not silently promoted

The integration explicitly rejects these equivalences:

`process vocabulary ≠ process ontology`

`source-born family ≠ authorial doctrine`

`family recurrence ≠ philosophical adequacy`

`local composition ≠ global synthesis`

`routing success ≠ semantic truth`

`synthetic regression success ≠ external validation`

`POLYPHONIC_GLOBAL_ABSTENTION ≠ proof that no global thesis exists`

The regression corpora validate execution mechanics only.

## Next architectural pressure

The new family is still developer-specified. The strongest next step is not to add another hard-coded family. It is to create an adversarial **family-induction protocol** that proposes distinctions from source-native patterns, compares them against existing families, perturbs vocabulary and polarity, and requires blinded semantic review before retention.

The governing question becomes:

> Can a source force a genuinely new way of asking without allowing the engine to mistake lexical novelty for conceptual novelty?
