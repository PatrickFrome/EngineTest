# Destruktion 4.0 — Development Report 0.9

## Stage
**Executable Operator Evolution / Genetic–Ecological Merge**

0.9 joins the executable mutation branch recovered from COMPLETE/Studio 0.3 with the source-resistance, cross-corpus regression and local operator-competition ecology of 0.8.

## New runtime path
`SOURCE RESISTANCE → OPERATOR DELTA → MUTATION GATE → CANDIDATE REGISTRY → LIVING CYCLE WITH CANDIDATE → REGRESSION → COMPETITION → RETAIN / QUARANTINE / RETIRE / ABSTAIN`.

The candidate registry is never silently promoted. Every accepted mutation produces a rollback target.

## Architectural changes
- `living_operator_registry.json` is now an executable declarative registry.
- GX1–GX7 activation and emission can be data-driven without gesture-id-specific runtime code.
- `operator-mutation` CLI command gates `SUSPEND`, `SPLIT`, `REVISE`, and supported condition changes.
- `living-cycle --registry <candidate.json>` can execute a gated candidate registry directly.
- Engine version is now read from `package.json`, reducing release-lineage drift.
- 0.8 operator regression and competition remain in place downstream of mutation.

## Epistemic invariant
Operator novelty is not evidence. A source-born operator is only a reversible candidate until same-source contrast, traceability, negative tests, regression and local competition support retention.

## Remaining limit
0.9 makes operator birth executable, but does not yet solve open-set discovery of entirely unknown operator families or micro-local passage routing. Those are the next research targets.
