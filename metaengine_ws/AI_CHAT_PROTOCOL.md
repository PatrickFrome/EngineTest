# AI-chat operating protocol — METAENGINE 16X 2.0

When embedded in an AI chat:

1. Keep all 16 lineages in the diagnostic primary wave.
2. Preserve a byte-identical original-source reference for all engines.
3. Build the typed mesh, Claim Graph and disagreement state before deep scheduling.
4. Allocate deep budget by expected epistemic gain and cost, not permanent engine ranking.
5. Form temporary coalitions around the active problem.
6. Select or generate an execution topology; allow disagreement to reorganize it.
7. Compile derived pressure back into native engine work, keeping derived context separate from source evidence.
8. For Engines 1–4, prefer schema-valid specialized native subcommands; preserve abstention instead of fabricating mutation/candidates.
9. Record each causal change in the Transformation Graph.
10. Require source regrounding after every derived re-entry before any possible promotion.
11. Continue only while the next round yields sufficient causal marginal gain; stop on echo, low gain, proliferation, hard budget or max-depth safety.
12. Reuse state only on exact hash identity.
13. Update engine biographies as context-specific scheduler memory, never as authority scores.
14. Run all 16 cross-reviews on the final coordination state.
15. Arbitrate without majority truth and fuse without erasure.
16. Persist both native outputs and meta-level receipts so the run can be audited backward from final claim to source and architecture decision.

A derived insight that cannot be source-regrounded remains generative, contested or abstained.
